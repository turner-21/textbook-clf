① クラウドコンセプト

クラウドの価値提案 / クラウド経済性 / クラウド設計の基本原則

このドメインは「そもそもクラウドはなぜお得で、なぜ速いのか」という考え方を問うパートです。サービス名の暗記より、従来のIT(オンプレミス)と何が違うのかを自分の言葉で説明できることが重要です。

1-1 クラウドの6つの価値提案

AWSは自社サーバーを持つ代わりに、クラウドを使う理由として次の6つの利点を掲げています。試験ではこの6つの「言い換え表現」が選択肢に紛れ込むので、意味とセットで覚えましょう。

覚え方: 「固定→変動」「規模の経済」「予測不要」「速い」「楽になる」「世界へ」の6語を順番に唱えるだけでOK。試験では言い回しが変わっても意味が一致すれば正解です。

1-2 クラウドの経済性:Capex から Opex へ

従来のオンプレミス(自社データセンター)は、ピーク時の需要を予測して先に一括で機器を購入する必要がありました(Capex=資本的支出)。一方AWSクラウドでは、使った分だけ後から支払うため(Opex=運用的支出)、需要に合わせて容量を伸縮でき、無駄がありません。

この考え方を数値で比較するツールがAWS Pricing CalculatorやTCO Calculatorです。オンプレミス運用とAWS運用の総保有コスト(TCO: Total Cost of Ownership)を試算し、経営層への説明資料として使われます。

1-3 クラウド設計の基本原則

AWS上でシステムを設計する際に意識すべきキーワードです。似た言葉が並ぶため、混同しやすいポイントでもあります。

用語意味ひとことイメージ
可用性 (Availability)システムが継続して利用できる度合い止まらない
弾力性 (Elasticity)需要に応じて自動でリソースを増減できる性質伸び縮みする
俊敏性 (Agility)新しいリソースを素早く用意・試行できる性質すぐ試せる
耐障害性 (Fault Tolerance)一部が故障してもサービス全体は継続する性質壊れても平気
疎結合 (Loose Coupling)コンポーネント同士の依存を減らし、個別に変更・拡張できる設計部品ごとに独立
ひっかけ注意: 「アクセスが急増したので自動でサーバー台数が増えた」は弾力性(Elasticity)の例です。「新機能のテスト環境を10分で作れた」は俊敏性(Agility)の例。この2つの選択肢を入れ替えて出題されることが非常に多いです。
ひっかけ注意: TCO Calculatorは「AWSの月額料金を見積もるツール」ではなく、オンプレミス運用とAWS運用のコストを比較するツールです。月額見積もりは AWS Pricing Calculator の役割です。

D. すべて無償になる

A. 俊敏性(Agility)
B. 耐久性(Durability)
C. 弾力性(Elasticity)
D. 可用性(Availability)

正解: C — 需要に応じて自動でリソースが伸縮する性質が弾力性です。
Q3オンプレミス運用とAWS運用の総保有コストを比較する際に使うツールはどれか。
A. AWS Budgets
B. AWS Cost Explorer
C. TCO Calculator
D. AWS Trusted Advisor

正解: C — TCO Calculatorはオンプレミスとクラウドのコスト比較に特化したツールです。
Q4「新規プロジェクト用の開発環境を、申請から数分で用意できた」という事例が示すクラウドの利点はどれか。
A. スケールメリット
B. 俊敏性(Agility)
C. 耐障害性
D. 疎結合

正解: B — 新しい環境を素早く試せる性質が俊敏性です。
Q5多くの顧客がAWSのインフラを共有して利用することで、AWSの調達コストが下がり利用料金にも還元される仕組みを何と呼ぶか。
A. 規模の経済(Economies of Scale)
B. 責任共有モデル
C. マルチAZ構成
D. リザーブドインスタンス

正解: A — 利用者が増えるほど単価が下がる仕組みが規模の経済です。
配点 30%

② セキュリティ・コンプライアンス

責任共有モデル / IAM / セキュリティ関連サービスとリソース

配点が最も高い30%を占める最重要ドメインです。中心となるのは「どこまでがAWSの責任で、どこからがお客様の責任か」を理解する責任共有モデルと、「誰に何を許可するか」を管理するIAMです。

2-1 責任共有モデル (Shared Responsibility Model)

AWSと利用者は、セキュリティの責任を分担します。AWSは「クラウドそのもの」の安全を守り、利用者は「クラウドの中に置いたもの」の安全を守ります。

覚え方: AWS = 「Of(建物・土台)」/ お客様 = 「In(中身)」。頭文字で Of → 下段、In → 上段 と覚えると図とリンクします。

2-2 IAM(Identity and Access Management)の全体像

「誰が(Identity)」「何に(Resource)」「何をしてよいか(Permission)」を管理する仕組みがIAMです。ルートユーザーは普段使わず、日常操作にはIAMユーザーやロールを使うのがベストプラクティスです。

種類特徴ベストプラクティス
ルートユーザーアカウント作成時に自動生成される最上位権限MFAを設定し、日常操作には使わない
IAMユーザー個人やアプリケーションに紐づく恒久的な認証情報最小権限の原則で必要な権限のみ付与
IAMグループ複数ユーザーをまとめて同じ権限を付与する箱役割ごと(開発者/経理など)にグループ化
IAMロール必要なときだけ引き受ける一時的な権限EC2やLambdaなどサービスに付与するのが基本

2-3 主なセキュリティ関連サービス

サービスひとことで言うと
AWS ShieldDDoS攻撃からインフラを守る盾
AWS WAFWebアプリへの不正リクエストを検査するファイアウォール
Amazon GuardDutyアカウント内の不審な挙動を継続的に検知する監視役
AWS KMS暗号化キーを一元管理する金庫
AWS Artifactコンプライアンス関連の監査レポートを取得できる資料庫
Amazon InspectorEC2やコンテナの脆弱性を自動スキャン
AWS Configリソースの構成変更履歴を記録・追跡
AWS Organizations複数アカウントをまとめて管理・統制
ひっかけ注意: Shield(DDoS対策)・WAF(Webリクエストのフィルタ)・GuardDuty(脅威の検知・監視)は役割が異なります。「守る対象」で覚えましょう:Shield=インフラ全体、WAF=Webアプリの入口、GuardDuty=異常の発見。
ひっかけ注意: AWS Artifact(コンプライアンス"文書"の取得)とAWS Config(リソース"設定変更"の記録)は名前が似ていますが用途が全く異なります。

確認問題 ドメイン② 理解度チェック

Q1責任共有モデルにおいて、AWSが責任を負う範囲はどれか。
A. EC2インスタンス上のOSパッチ適用
B. データセンターの物理的セキュリティ
C. IAMユーザーのパスワード管理
D. アプリケーションのデータ暗号化

正解: B — 物理的な設備やハードウェアの保護は「クラウド"自体"の安全」としてAWSの責任範囲です。
Q2複数のIAMユーザーに同じ権限をまとめて付与したい場合、最も適切な方法はどれか。
A. 各ユーザーにルートユーザーの認証情報を共有する
B. IAMグループを作成し、そこにユーザーを追加する
C. すべてのユーザーで1つのIAMユーザーを共用する
D. IAMロールをユーザーに永続的に割り当てる

正解: B — 同じ権限が必要な複数ユーザーはIAMグループでまとめて管理するのが基本です。
Q3アカウント内の不審なAPI呼び出しやポートスキャンなどの脅威を継続的に検知するサービスはどれか。
A. AWS Shield
B. Amazon GuardDuty
C. AWS WAF
D. AWS Artifact

正解: B — Amazon GuardDutyはアカウント内の異常な挙動を継続的に監視・検知します。
Q4監査対応のため、AWSのコンプライアンス認証レポートを入手したい。利用すべきサービスはどれか。
A. AWS Config
B. AWS Trusted Advisor
C. AWS Artifact
D. Amazon Inspector

正解: C — AWS Artifactはコンプライアンス関連の各種レポートをオンデマンドで取得できるサービスです。
Q5EC2インスタンスからS3バケットへ安全にアクセスさせたい。ベストプラクティスはどれか。
A. IAMユーザーのアクセスキーをEC2にハードコーディングする
B. ルートユーザーの認証情報を使う
C. EC2インスタンスにIAMロールを割り当てる
D. S3バケットを全世界に公開する

正解: C — サービス間のアクセスにはアクセスキーの埋め込みではなく、一時的な権限を発行するIAMロールを使うのがベストプラクティスです。

③ クラウド技術・サービス

デプロイ・運用方法 / グローバルインフラ / 主要サービス / 技術サポート

配点34%と最大のドメインです。範囲は広いですが、「AWSにどう指示を出すか」「世界のどこで動いているか」「代表的なサービスは何か」の3点セットで整理すると覚えやすくなります。

3-1 AWSへのアクセス・デプロイ方法

AWSの操作方法は用途によって使い分けます。特にIaC(Infrastructure as Code)は「手順書ではなくコードでインフラを再現可能にする」考え方として頻出です。

デプロイモデル特徴向いているケース
クラウドすべてのリソースをAWS上で運用新規サービス、スケール重視
オンプレミス自社データセンターで完結規制上クラウド利用が難しい環境
ハイブリッドオンプレミスとAWSを組み合わせて運用段階的な移行、既存資産の活用

3-2 AWSグローバルインフラストラクチャ

AWSは世界中にリージョンを持ち、各リージョンは独立した複数のアベイラビリティーゾーン(AZ)で構成されます。さらに、コンテンツ配信を高速化するエッジロケーションが世界中に分散配置されています。

グローバルサービス vs リージョナルサービス: IAM・Amazon Route 53・Amazon CloudFrontなどはすべてのリージョンで共通(グローバル)のサービスです。一方EC2やRDSなどほとんどのサービスはリージョン単位で作成・管理します。

3-3 主要サービスの全体像

試験範囲は広大ですが、CLFレベルでは「カテゴリと代表サービス」のペアで覚えれば十分です。

ひっかけ注意: EC2(常時起動のサーバー、自分で管理)とLambda(コード実行時のみ課金、サーバー管理不要)は対比でよく出題されます。「サーバーレス」というキーワードが出たらLambdaを疑いましょう。
ひっかけ注意: Auto Scaling(サーバー台数を需要に応じ自動調整)とElastic Load Balancing(複数サーバーへ通信を振り分け)は必ずセットで機能しますが、役割は別物です。

3-4 技術サポートのためのリソース

リソース役割
AWS Documentation各サービスの公式ドキュメント
AWS Whitepapersベストプラクティスをまとめた公式技術文書
AWS re:PostAWSが運営するQ&Aコミュニティ
AWS Well-Architected Tool設計を6つの柱に沿ってセルフレビュー
AWS Trusted Advisorコスト・パフォーマンス・セキュリティ等を自動診断

④ 請求・料金・サポート

料金モデル / コスト管理ツール / サポートプラン

配点は最も低い12%ですが、出題範囲が狭い分、確実に得点できるドメインです。料金モデルの種類とサポートプランの違いを表で押さえましょう。

4-1 4つの料金モデル

覚え方: 割引の大きさは「スポット > リザーブド ≒ Savings Plans > オンデマンド」。柔軟性はその逆順。「割引が欲しければ、その分自由を手放す」と覚えると迷いません。

4-2 コスト管理ツール

ツール役割
AWS Pricing Calculator利用前に月額費用を見積もる
AWS Cost Explorer過去〜現在の利用料金をグラフで可視化・分析
AWS Budgets予算を設定し、超過しそうな時にアラート通知
AWS Cost and Usage Report最も詳細な利用データをCSV等で出力
Consolidated Billing複数アカウントの請求を一本化し、割引をまとめて適用

4-3 サポートプランの比較

プラン想定利用者特徴
Basicすべての利用者無料。ドキュメントやフォーラムなどセルフサービスのみ
Developer検証・開発段階メール中心の技術サポート
Business本番環境で運用中24時間365日、電話・チャット・メールで対応
Enterpriseミッションクリティカルな運用専任の技術担当(TAM)が付き、最優先で対応
ひっかけ注意: Basicサポートは無料ですが、電話やチャットでの個別サポートは含まれません。「無料=フル対応」ではない点が狙われます。
ひっかけ注意: 無料利用枠(Free Tier)には「12か月間無料」「常に無料」「トライアル」の3種類があり、サービスによって条件が異なります。
